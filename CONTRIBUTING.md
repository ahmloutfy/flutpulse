# 🧩 Contribution Guide

Thanks for your interest in contributing to **FlutPulse**! 💙
We’re excited to collaborate with developers and designers who share our passion for clean, beautiful Flutter UI.

---

## 🧠 Before You Start

1. **Explore the Repository**
   Take a look at the existing templates and UI kits to understand our structure and style.

2. **Check for Existing Issues**
   Browse [Issues](../../issues) to see if someone has already suggested your idea.

3. **Open a New Issue (if needed)**
   If it’s something new — feel free to open a new issue.
   Describe your idea clearly, include screenshots or mockups if possible.

---

## ⚙️ How to Contribute

### 🧱 For Code Contributions

1. **Fork the repo** and clone your copy.
2. **Create a new branch** for your changes:

   ```bash
   git checkout -b feature/new-ui-screen
   ```
3. **Make your changes** (keep code clean and consistent).
4. **Test locally** — make sure it runs without errors.
5. **Commit and push** your changes:

   ```bash
   git commit -m "Add: new onboarding screen template"
   git push origin feature/new-ui-screen
   ```
6. **Open a Pull Request** with a short summary of your changes.

---

### 🎨 For Design Contributions (Figma or UI ideas)

If you’re a designer or just want to share layout ideas:

* Attach your **Figma link**, **screenshots**, or **mockups** in a new issue.
* Briefly explain the **use case** and **intended UX goal**.

---

## ✅ Contribution Guidelines

* Keep code **clean, readable, and reusable**.
* Follow **Flutter best practices** (naming, folder structure, responsiveness).
* Avoid adding external packages unless necessary.
* Keep commit messages short and descriptive.

---

Together, we can make **Flutter UI development faster, cleaner, and more creative**. 🚀
Thanks for contributing to **FlutPulse**!
